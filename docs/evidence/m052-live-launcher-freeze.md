## 3. Phase 2 — the launcher

`baby_workspace\m052_launch.cmd`, 8079 bytes, generated by `tests/m052_launcher.py`. The source of
record is that module; the `.cmd` is a build artefact.

### 3.1 Two modes, one template

The launcher is rendered from a single template in two modes:

* **`live`** — the real launcher. Targets the **existing production** `subject_runtime`,
  observe-only. Creates `%TEMP%\TharAI_M052_live`.
* **`rehearsal`** — identical plumbing, operator stands in for the subject, disposable root.

The lines that actually matter — hash guards, writer start, bounded waits, subject leg, readback —
are **byte-identical** between the two, and that is asserted rather than asserted-by-comment:

```
live plumbing lines captured      : 26
rehearsal plumbing lines captured : 26
BYTE-IDENTICAL                   : True
```

The complete set of differences between the two renderings is:

```
MODE=live            <-> MODE=rehearsal
TARGET_ROOT=…\subject_runtime   <->  TARGET_ROOT=…\TharAI_M052_launch_rehearsal
LIVE_ROOT=…\TharAI_M052_live    <->  LIVE_ROOT=…\TharAI_M052_launch_rehearsal\evidence
runas /user:…BABY_AI_TEST …     <->  "%CLIENT%" …        (the subject leg itself)
```

The only substantive difference is the one that cannot be rehearsed without a subject.

### 3.2 Why the launcher verifies its own hashes

M052A proved the *instrument*. What remained unproven was that the thing a human executes **is**
that instrument. A launcher that trusts a path rather than a digest runs whatever happens to be at
that path. So the launcher hashes the frozen client executable and the frozen M049 writer source
itself and refuses on mismatch (exit 92) — the same discipline `tests.m044_preflight --gate`
applies from outside, now also applied from inside.

### 3.3 Fail-closed conditions in the launcher

| Condition | Exit | Meaning |
|---|---|---|
| client absent | 90 | setup failed, nothing launched |
| operator python absent | 90 | setup failed |
| target root absent | 90 | **observes an existing boundary; never creates one** |
| live root not creatable | 90 | setup failed |
| artefact already exists | 91 | **refuses to reuse a root holding an artefact** |
| nonce generation failed | 90 | setup failed |
| client / writer hash mismatch | 92 | instrument is not the frozen one |
| writer never signalled ready | 93 | **nothing launched, NO ATTEMPT CONSUMED** |
| artefact never appeared | 94 | **attempt IS consumed** — preserve evidence |

The 93/94 split matters: a writer that never came up consumes nothing, while a subject leg that ran
and produced no artefact *is* a consumed attempt. The launcher distinguishes these rather than
reporting one generic failure.

### 3.4 What the launcher does not contain

Verified by scanning the frozen launcher text:

```
icacls      0      /grant   0      /deny    0
del         0*     rmdir     0      rd       0
mkdir       1      -> if not exist "%LIVE_ROOT%" mkdir "%LIVE_ROOT%"
model       2      -> both occurrences are the words "model/ is NOT created"
runas       1      -> the single subject leg
```

*\* `del ` / `md ` substring counts were false positives from `mo`**del** ` and `c`**md** `; the
line-level scan above is authoritative.*

The launcher creates **only** its own fresh evidence root, guarded by `if not exist`. It performs no
recursive deletion and never reuses an existing evidence root.

### 3.5 Credentials

None appears in the launcher, none is stored, none is echoed, none is logged, and `/savecred` is
never emitted. If `runas` prompts, the **human** types the password into the Windows dialog. The
launcher header states this in-band.

## 5. Six defects found by the rehearsal

Every one of these would have converted the single authorised live attempt into a debugging session.

| # | Defect | Symptom | Root cause |
|---|---|---|---|
| 1 | Dead `for %%%%F in ("%CLIENT%")` line | exit **255**, `%%F was unexpected at this time` | the template goes through `str.format()`, which does not consume `%`, so the doubled form reached `cmd` literally. Removed — the line set a variable nothing read. |
| 2 | Hash guard refused a **correct** binary | exit **92**, `CLIENT_HASH_MISMATCH:63893e34…` while both sides were identical | the launcher `set "EXPECT_CLIENT_SHA256=…"` but the guard read `%CLIENT_SHA%`, which expanded to empty. The guard **worked**; its wiring did not. |
| 3 | Rehearsal leg used `""%CLIENT%"` | exit **123**, *"The filename, directory name, or volume label syntax is incorrect"*, client never ran, writer timed out `no_client_within_timeout` | doubled quoting is only correct as a single `runas` **argument**. The code contradicted the comment directly above it. |
| 4 | `render("rehearsal")` wiped the fixture | 4 of 6 operations falsely **DENIED** | the renderer `rmtree`d and recreated the rehearsal root, destroying the ACL-shaped fixture built moments earlier; the client then found an empty tree. |
| 5 | `production_root() in text` | `TypeError: 'in <string>' requires string as left operand` | `Path` compared against `str`. |
| 6 | `model\ was` in template | `SyntaxWarning: invalid escape sequence` | single backslash in a non-raw Python string. |

Defects 1, 3 and 4 share a single lesson worth recording: **the rehearsal is what makes the
plumbing trustworthy, and each of these was invisible to inspection.** Defect 2 is the more
interesting shape — a guard that fires for the wrong reason. It was correct to refuse, and wrong to
refuse; had the digest genuinely differed, the same wiring would have produced the *right* refusal
and nobody would have noticed the fault. A guard is only as trustworthy as the test that it fires
for the intended reason.

## 10. Interpretation boundary

A successful M052 live measurement would establish **only** the observed subject-side filesystem
and access behaviour for these six operations, on the existing production boundary, for that one
attempt.

It would establish **nothing** about cognition, consciousness, subjective experience, agency,
learning, memory, inference, model execution, birth, usefulness discovery, or developmental
progress. None of those may be inferred from filesystem behaviour, token identity, or process
behaviour.

Equally, this freeze record does **not** upgrade:

> "the M052 instrument is mutation-free"

into

> "the Baby AI cannot mutate production."

That second statement remains **unmeasured**. The rehearsal establishes only that the measurement
apparatus can make these observations without itself introducing a mutation capability.

And the standing production finding is unchanged: the subject has **0 explicit ACEs** but an
effective access of `0x001301BF` — i.e. `T-WR = NOT_SATISFIED`, with `write`, `append`, `delete`,
`write_ea` and `write_attributes` all present. M052 is purely observational and **must not modify
production ACLs to make the six operations return their expected results.** It observes the state
