## A real defect found: the parser could not accept a valid decision

M052T names three forms as **valid** selections. Two parsed; one did not:

```
"I select R1."                                  -> R1     ok
"My RECOVERY_GOVERNANCE decision is R2."        -> None   REFUSED  ← defect
"I select R3 as the recovery governance class." -> R3     ok
```

The field pattern demanded `=` or `:` immediately after the name, so the natural-language declaration
`decision is R2` matched nothing. The failure was silent and shaped exactly like correctness: the
intake returned a clean refusal with a plausible reason, so a director who had genuinely decided R2
would have been told "no decision supplied" and the milestone would have looped — the precise
failure M052S was built to end.

Fixed by adding an anchored declaration pattern (`decision is|=|: Rn`), which admits an explicit
declaration without admitting opinion. All eight M052T-named invalid forms still refuse, and all
previously accepted forms still parse. Three tests added, including one asserting the
declaration pattern does not admit *"which decision is better, R1 or R2"*.
